# 개인정보 원칙

이 저장소는 공개를 전제로 합니다. 한 번 공개된 내용은 git 기록, 포크, 검색 캐시에 남아 지울 수 없습니다. 그래서 **걸러서 올리는 방식이 아니라, 원본을 아예 들이지 않는 방식**으로 운영합니다.

## 저장소에 절대 넣지 않는 것

- 참여자 이름, 연락처, 주소, 생년월일, 주민등록번호, 장애 등록 정보
- 진단명·병력 등 건강 정보 원문 (설계에 필요한 기능적 조건만 적습니다. 예: "엄지 대립 어려움", "악력 약함")
- 인터뷰 녹음·녹화, 녹취 원문, 동의서
- 얼굴이 보이는 사진, 집 내부가 특정되는 사진, 위치 정보(EXIF GPS)가 남은 사진
- 협력기관 담당자 개인 연락처

원본 자료는 팀 내부 비공개 드라이브에 보관하고, 프로젝트 종료 후 동의서에 적은 기간이 지나면 파기합니다.

## 저장소에 넣는 것

- 사례 ID(`case-01` 등)로만 식별되는 요구사항, 치수, 설계, 평가 기록
- 설계에 필요한 신체·환경 치수 (예: 손잡이 둘레, 문고리 지름, 작업면 높이)
- 손·기기만 나오고 EXIF를 지운 사진 (참여자의 사진 공개 동의를 받은 경우에만)

## 동의

첫 면담 전에 다음을 각각 따로 동의받습니다: 인터뷰·측정, 사진 촬영, 익명화된 결과 공개(이 저장소와 보조기기 공공 플랫폼). 공개 동의가 없는 사례는 설계 파일만 공개하고 평가 기록은 공개하지 않습니다. 참여자는 언제든 공개 철회를 요청할 수 있으며, 그 경우 해당 사례 폴더를 삭제합니다(이미 퍼진 사본까지 회수할 수는 없음을 동의 시 안내합니다).

## 커밋 전 확인

```sh
python3 tools/check_privacy.py      # 전화번호·주민번호·이메일 패턴 검사
exiftool -all= photos/*.jpg         # 사진 메타데이터 삭제 (exiftool 설치 필요)
```

`check_privacy.py`는 GitHub Actions에서도 매 push마다 실행됩니다. 이것은 안전망일 뿐입니다. 사진의 얼굴, `note`에 적힌 이름 같은 것은 기계가 잡지 못하므로 사람이 직접 확인합니다.

## 사례 ID 규칙

`case-01`, `case-02`… 처럼 순번만 씁니다. 이니셜, 동네 이름, 기관 이름을 섞지 않습니다. ID와 실제 참여자의 대응표는 비공개 드라이브에만 둡니다.
