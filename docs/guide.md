# 맞춤형 보조기기 제작 가이드

> 상태: **초안 (2026-11)**. 프로젝트 진행 중 시행착오를 반영해 12월 최종본으로 정리합니다. 아직 실제 사례로 검증되지 않은 절차는 "계획"이라고 표시합니다.

한 사람의 구체적인 일상동작 문제를 정의하고, 기존 공개 설계를 먼저 검토해 맞춤 제작한 뒤, 실제 생활에서 써 보고 고쳐서, 다음 제작자가 다시 쓸 수 있도록 공개하는 절차입니다.

```
문제 확인 → 요구조건 정의 → 기존 설계 검토 → 설계·제작 → 전달 전 점검
   → 실사용(≥14일) → 평가 → 개선(≥1회) → 최종 전달 → 공개
```

## 0. 범위

**만드는 것**: 식사, 필기, 문 열기, 물건 잡기처럼 특정 일상동작 하나를 돕는, 손·팔로 쓰는 생활 보조도구.

**만들지 않는 것**: 체중을 지지하는 기기(지팡이·보행 보조·이승 보조 등), 치료 효과를 목적으로 하는 기기(교정용 보조기·스플린트 등), 전기·전자 안전 검증이 필요한 기기. 학생팀이 충분히 검증할 수 없기 때문입니다. 경계가 애매하면 협력기관 전문가 의견을 받고, 그래도 애매하면 만들지 않습니다.

## 1. 사용자 발굴 및 문제 정의 (10월 1–3주)

1. 지역 복지관, 장애인자립생활센터, 보조기기센터에 협력을 요청해 참여자를 소개받습니다.
2. 면담 전에 [개인정보 원칙](privacy.md)에 따라 동의를 받습니다.
3. **필요한 제품을 미리 정하지 않습니다.** 면담에서는 다음을 묻습니다 (`cases/_template/01-interview.md`).
   - 매일 반복되는데 어려운 동작은 무엇인가
   - 지금은 어떻게 해결하고 있는가 (누가 도와주는가, 얼마나 자주)
   - 써 본 제품이 있는가, 왜 그만두었는가
4. 동작 하나를 고릅니다. 기준은 빈도와 본인이 느끼는 필요성이고, 만들기 쉬운지는 기준이 아닙니다.
5. 기기 없이 목표 동작을 해 보도록 하고 `baseline`을 기록합니다 ([평가 기준](evaluation.md)).
6. 필요한 치수를 측정합니다 (`02-requirements.md`): 손 크기·쥘 수 있는 지름, 움직임 범위, 사용 자세, 기기가 놓일 공간의 치수, 작업면 높이, 동선.

**산출물**: 측정값이 들어간 요구사항 표. "잡기 편하게"가 아니라 "외경 30–35 mm, 무게 60 g 이하, 한 손으로 착용"처럼 확인 가능한 조건으로 씁니다.

## 2. 설계 및 1차 시제품 (10월 4주 – 11월 2주)

1. **기존 설계를 먼저 찾습니다.** [선행 사례 조사](prior-art.md)의 라이브러리(국립재활원 열린페이지, 경기도 3D보조기기 공공 플랫폼, Makers Making Change, Printables·Thingiverse)를 검색합니다. 쓸 만한 설계가 있으면 라이선스를 확인하고 치수만 바꿉니다.
2. 없으면 새로 설계합니다. 사용자 치수가 바뀌어도 다시 만들 수 있도록 **매개변수(parametric) 설계**를 권합니다. 이 저장소의 [`cad/`](../cad/)에 시작점이 되는 OpenSCAD 모델이 있습니다.
3. 무엇을 왜 바꿨는지 `03-design-rationale.md`에 씁니다. 원본 설계를 수정했다면 출처와 라이선스를 반드시 적습니다.
4. 소재를 고릅니다. 일반적인 출발점은 다음과 같습니다.
   - PLA: 빠르게 형태를 확인하는 시제품. 열(식기세척기, 뜨거운 물)과 충격에 약합니다.
   - PETG: 실사용품의 기본값. PLA보다 열·충격에 강합니다.
   - TPU: 손에 닿는 부분, 미끄럼 방지, 압박을 줄여야 하는 부분.
   - 식기에 쓰는 부품은 입에 닿지 않게 설계하고, 적층 틈에 음식물이 남을 수 있음을 사용자에게 안내합니다.
5. 출력 조건, 부품 목록(벨크로·패딩·고무패드·체결부품 포함), 조립 방법을 `04-build.md`와 `bom.csv`에 기록합니다.

## 3. 전달 전 점검

`05-pre-delivery-check.md`의 항목을 모두 확인한 뒤에만 전달합니다: 반복 작동, 체결 상태, 날카로운 모서리·버, 파손 가능 부위, 피부 접촉부, 세척 방법. 하나라도 통과하지 못하면 고쳐서 다시 점검합니다.

## 4. 실사용 평가 및 개선 (11월 3주 – 12월 1주)

1. 1차 시제품을 전달하고 사용법과 중단 기준(통증·발적·파손 시 즉시 사용 중지 후 연락)을 안내합니다.
2. **최소 14일** 실제 생활에서 사용하도록 합니다. 중간에 한 번 연락해 문제가 없는지 확인합니다.
3. 14일 후 `v1` 평가를 기록합니다. 만족도가 아니라 목표 동작이 실제로 나아졌는지를 봅니다.
4. 결과를 설계 변경사항으로 바꿔 `CHANGELOG.md`에 적고, 개선품을 만듭니다(최소 1회). 다시 점검하고 전달해 `v2`를 기록합니다.

선행 연구에서 반복적으로 나오는 교훈은, **후속 확인 없이 한 번 전달된 맞춤 기기는 쓰이지 않게 되기 쉽다**는 것입니다. 이 단계를 생략하지 않는 것이 이 절차의 핵심입니다.

## 5. 설계 공개 및 결과 정리 (12월 2–4주)

1. 사례 폴더에 최종 CAD 원본(`cad/`), STL(`stl/`), 출력 조건, 부품 목록, 조립 방법, 개선 이력이 모두 있는지 확인합니다.
2. `python3 tools/check_privacy.py`와 사진 EXIF 삭제를 거칩니다.
3. 공개 동의 범위 안에서 이 저장소와 보조기기 공공 플랫폼에 등록합니다.
4. `python3 tools/at_eval.py`로 정량 목표를 확인하고, 이 가이드에 실제로 겪은 시행착오를 추가합니다.
